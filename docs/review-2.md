# 低軌道旅行 — レビュー 2（実装 cbfe910 時点）

> レビュー: Fable 5.1 ／ 対象: `main` @ cbfe910（2026-09-29）、公開版、クライアント提供のスクリーンショット 3.webp / 4.webp、参照画 ref1/ref2、直近の実機キャプチャ（R3b/R3c/G-*/FINAL-*）。
> 読み取れなかった点・実機未計測の点は「確度」を明記した。数値は概算。

## 0. 総評

- 骨格（軌道・太陽・視点切替・スキップ・生成音・モバイル必須項目）は §13 の決定をほぼ満たし、コードの質も高い。
- 一方で開発順序が §13（M0→M1→音→**撮影＋現像**→現象群）から外れ、直近 10 コミット中 8 つが描画の作り込み。**主仮説（撮影で再訪が伸びるか）を検証する手段がまだ無い。**
- 見た目は「写実の劣化版」からは脱したが、参照画（ref1/ref2）との差は **①低い太陽での陰影設計、②面の粗さと乱数、③加算される霞** の 3 点に集約できる。いずれもシェーダ数十行の範囲で直せる。
- モバイル性能の最大要因は「対数深度で early-Z が効かないまま、全画面のシェーダを 4〜5 枚重ねている」こと。面数ではない。

## 2. 見た目：参照画・指摘との差の原因

### 2.1 (a) 3.webp — 雲の上の「墨のような筋」

**最有力の原因：上層雲（ジェット気流の巻雲）の影を下層の雲面に落としている処理。** `clouds.ts` L206–215：

```glsl
vec4 fm = cloudFieldsFast(normalize(q + tang * max(CL_MID - hKm, 0.0) * k));
occ = max(occ, smoothstep(0.0, 0.4, fm.b) * mix(0.2, 0.55, smoothstep(0.35, 0.7, fm.b)) * step(hKm, CL_HIGH));
shade = 1.0 - occ;
...
vec3 tone = mix(uLowShade, uLowLit * sun.rgb, light * sun.w * shade);
```

- 巻雲の形は `cloudMap.ts` L343–347 の「ジェットに沿って長く・直交方向に細い」筋（`streak`）で、これが 1024×512 のマクロ場 B に入る。3.webp の筋がすべて平行で斜めなのは、ジェットに沿った筋を斜めから見ているため。
- 影の濃さは最大 55 % で、`uLowShade`（青灰 0x8d99b3）へ寄せる。白い雲面の上では「灰色の筋」になる。
- 一方、**影を落としている巻雲自体はほぼ見えない**（`highLayer` の alpha は薄い巻雲で 0.4、色は白 0xfbf8f2 で白い雲面と区別がつかない）。影だけが見えるので「墨」に見える。
- 追加要因：影のオフセットが `CL_MID`（22 km）で計算され、高層 46 km の雲の影が真下寄りに落ちる（形はそのまま）。

**検証**：`shade = 1.0;` を仮に入れて筋が消えるか。`__cloudsVisible(1)`（上層を隠す）では消えない点も傍証になる（影は下層シェーダ内で計算されるため）。
**対処**：(1) 高層雲の影は 0.15 程度に落とし、中層・積乱雲の影のみ残す。(2) 巻雲を可視化したいなら alpha ではなく明度差（雲面より僅かに暖色・明るく）で。(3) 影の輪郭を `fw` で滑らかに（現状はマクロ場をそのまま smoothstep）。

### 2.2 (b) 4.webp — 「ピンボケ」「立体感がない」

**確認：`post.ts` に被写界深度は無い**（RenderPass → UnrealBloom → Grade(vignette+grain) → Output）。ぼけて見えるのは複数の「コントラスト喪失」の足し算。原因を重い順に：

| # | 原因 | 場所 | 影響 |
|---|---|---|---|
| 1 | **低い太陽で全面が「影の階調」になる照明式** | `earth.ts` L195–198 | `wrap=(ndotl+0.35)/1.35`。太陽高度 13° の平地は ndotl≈0.22→wrap≈0.42。斜面 ±10° でも ±0.13 しか変わらず、**ほぼ全ファセットが同じ中間調**。さらに `shadeColor = mix(coolShadow, base, 0.32)`：影側は基調色 32 % で 68 % が青緑 0x2c5068 → 画面全体が青灰に。砂漠の黄が「たまに出る菱形」にしか残らないのはこのため |
| 2 | **落ち影・遮蔽がない** | 地形シェーダ全体 | 参照画の立体感は「日向の金」と「日陰の青」の**二値的な対比**。低い太陽ほど影が長いのに、現状は角度差だけで陰影を作るので低い太陽ほど平坦になる（写真と逆） |
| 3 | **ファセットが大きすぎる** | `earth.ts` L55–59 | 既定 level 8 ＝ 20·4⁸ ≈ 131 万三角形／全球 → 1 枚 ≈ 390 km² ≈ **一辺 30 km**（コメントの「~9 km」は誤り。level 9 で 15 km）。420 km からは 1 枚 ≈ 4°。シエラマドレ（幅 100〜200 km）が 3〜6 枚で表されるので「山脈」ではなく「格子」に見える |
| 4 | **地形の乱数が DEM を上回る** | `terrain.ts` L114–120 | `ridge=(ridgedFbm−0.3)×4 → ×5` で ±6〜14 km、波長 ≈ 150 km（周波数 260）。DEM 側は 2 km の山で 10 km。**山地では乱数が実地形と同程度以上**、しかもファセット 30 km は乱数波長の 1/5 で標本化不足 → 格子に沿った菱形模様（4.webp のパターンそのもの） |
| 5 | **ファセットごとの乱数明度 ±15 %** | `earth.ts` L180 | `grain = mix(0.82, 1.12, hash(flatN))`。形に無関係なノイズ＝「市松」に見える。参照画の面の変化は法線由来で、乱数ではない |
| 6 | **加算される霞** | `atmosphere.ts` L225–229、`earth.ts` L239–247 | 大気は AdditiveBlending で全画面に in-scatter を**足す**ので黒が持ち上がる（影は絶対に暗くならない）。`heightScale 1.5` で光学的厚みが実地球の 1.5 倍、`exposure 13` で 45° 見下ろしでも青灰の膜が乗る（見積り：線形 0.03〜0.06、sRGB で 0.2 前後。確度中）。地上側 `haze` と `uSkyAmbient*0.14` も同方向 |
| 7 | **グレイン＋ビネット＋ブルーム** | `post.ts` L51, L167 | grain 0.008 は低コントラスト画面では「ザラつき＝ピンボケ写真」に読める。ブルーム閾値 0.86 は、白飛びした地平線（R3b-natl-地平線）で画面上部に広く滲む |
| 8 | 適応解像度 | `index.ts` MIN_DPR 0.75 | 負荷時 0.75 まで落ちる。4.webp が 1257 px 幅なのは端末解像度の可能性もあり、寄与は不明（確度低） |

**要するに**：低い太陽で最も美しくなるはずの場面で、①照明式が平坦化し ②影が無く ③乱数と格子が形を壊し ④霞が黒を持ち上げている。参照画は逆に、低い太陽＋長い影＋高コントラストで成立している。

### 2.3 (c) その他、「軌道から見た美しさ」を損ねている点

| 項目 | 現状 | 根拠 |
|---|---|---|
| **地平線が白飛び** | R3b-natl-地平線 で大気層が幅広い白帯。参照画は細い青白の線→濃紺→黒の階調 | `ATMOSPHERE_SCATTER.exposure 13 / white 0.9 / heightScale 1.5`（`palette.ts` L325–348）。`white 0.9` で頭打ち→ブルーム閾値 0.86 を超えて滲む |
| **雲が均一な「ポップコーン」** | R3b-lowsun キューポラ：同じ大きさの粒が全面 | `F_DETAIL=400`（16 km）の単一スケール。参照画は数百 km の塊＋大きな影 |
| **雲の地上影が弱い** | 0.74 倍（`earth.ts` L216） | 参照画では雲の影が地形の立体感を補強している |
| **海が暗く平坦** | `deepOcean 0x1f4f7c`、`base*(0.45+0.6·ndotl)` | 参照画 2 の沿岸はシアン。浅海帯 3 px は幅が狭すぎて見えない |
| **宇宙船がほぼ無陰影** | FINAL-hero：日向と日陰の差が小さい | `STATION.ambientIntensity 2.17` vs `SUN.intensity 2.2`（`palette.ts` L266–277）。地球照としては強すぎる |
| **パレット規則の形骸化** | `palette.ts` は 60 色超 | art-direction §4「各時間帯 5〜7 色」は既に放棄。放棄自体は妥当だが、代わりの規則（例：地形は lit/shadow/haze の 3 色＋基調）が無いので色が増え続ける |
| 4 日周期でシェーダ時刻が巻き戻る | `SHADER_TIME_WRAP_S`（`index.ts`） | ×10 で 9.6 時間連続再生しないと起きない。実害は小さいが、雲のキーフレームと低気圧の寿命（`cloudMap.ts` L160, L232）が同時にリセットされる |

## 3. モバイル性能

### 3.1 現状の負荷見積り（未計測、コードからの推定）

| 項目 | 量 | 備考 |
|---|---|---|
| 三角形 | ≈ 25 万 | 粗球 2 万＋詳細 ≈84 チャンク×1,024 ＋ 雲殻 2×2.5 万 ＋ 大気 5 万 ＋ 船・キャビン。**問題ではない** |
| 描画呼び出し | ≈ 100 | 詳細チャンク 84 が大半。問題ではない |
| **画素あたり** | 地球を向いた画面で 4〜6 枚のフルスクリーン相当 | 地形（2 tex＋雲影 2 tex＋ノイズ 8 hash＋`pow(spec,4000)`）、雲下層（3D tex 2〜10＋タワー 4 步）、雲上層（3D tex 2〜6）、**大気 14 步（各 exp×3＋LUT）**、キャビン球、ブルーム 5 mip×2、グレード、出力 |
| **early-Z 無効** | `logarithmicDepthBuffer:true` | r186 の `logdepthbuf_fragment` は必ず `gl_FragDepth` を書く（確認済）。よって不透明でも**深度で捨てる前にシェーダが走る** |
| **裏面も描画** | `earth.ts` L304 `side: DoubleSide` | 球の裏半球は前半球と同じ画面領域を覆う → early-Z が無いので**地形シェーダが約 2 倍走る** |
| 粗球の重複 | 詳細チャンクの下の粗球も全画素シェーディング | 同上の理由で +1 枚 |
| MSAA 4x HalfFloat | ≈1350×620 で色 27 MB＋深度 | タイル GPU なら許容。HalfFloat の必要性は薄い（シェーダ内でトーンマップ済み、>1 は太陽スプライトと glint のみ） |
| 起動 | 陸マスク 2048×1024 のボックスぼかし 3 回（CPU、推定 100〜300 ms）、天の川ベーク 2048×1024 で ≈30 ノイズ/px（GPU、推定 100〜300 ms）＋同期 readback、雲マップ 2 キーフレーム、DEM 2048×1024 decode＋getImageData、地形チャンク 6/フレーム | 合計 1 秒前後（確度中）。タイトル画面の裏で走るので体感は小さい |
| 電池・熱 | フレーム上限なし | 120 Hz 端末では 120 fps で回る |

### 3.2 安い順の対策

| 対策 | 期待効果 | 工数 |
|---|---|---|
| **地形を `FrontSide` に** | 地形シェーダ約 −50 % | 1 行。skirt は 0 km なので裏面不要 |
| **大気の步数を分岐**：地面に当たる光線は 6 步、リム（`hc > −uDiscGraze`）だけ 14 步 | 大気コスト −40〜50 %（画面の大半は地面） | 数行 |
| **フレーム上限**：既定 30 fps、無操作 5 秒後 20 fps、設定で 60 | 電池・熱に最も効く（§12 で採用済の項目） | `main.ts` の rAF に間引き |
| MSAA を `UnsignedByteType` に | 帯域半減 | glint/太陽の >1 は失うが視覚差は小さいはず |
| ブルームを半分の半分（1/4 解像度）に | 5 mip の blur が軽くなる | 1 行 |
| 粗球のシェーダを簡略版に（雲影・glint・biome ノイズ無し） | +1 枚分の削減 | 材質を 1 つ追加 |
| キャビン球の `discard` を先頭へ（窓の内側なら計算せず捨てる） | 小 | 数行 |
| `reversedDepthBuffer: true`（r186 対応、`EXT_clip_control` 必須） | early-Z 復活で上記の重複描画が自然に消える | 対応ブラウザは要確認（確度低：iOS Safari で使えない可能性）。使えない端末は対数深度にフォールバック |

`?stats=1` に GPU 時間は出ないので、`EXT_disjoint_timer_query_webgl2` か端末の GPU プロファイラで **大気／雲／地形の 3 つを個別に A/B** してから手を付けるのが安全（`__cloudsVisible` は既にある。大気・ブルームにも同じフックを）。

資源解放：`dispose()` は各モジュールに揃っており、`detailCache` の逐次解放・イベント解除・`revokeObjectURL` も入っている。ページ寿命＝アプリ寿命なので実害は無いが、`composer.dispose()` は pass を解放しない（r186 は render target のみ）点だけ注意。

## 5. 推奨 7 項目（優先順）

| # | 項目 | 期待効果 | 工数（目安） |
|---|---|---|---|
| 1 | **低い太陽の陰影を作り直す**：(a) `wrap` を廃し、明暗を「その地点の平地の ndotl」を基準にした相対値にする（`lit = smoothstep(n0−a, n0+a, ndotl)`、n0 = 平地の ndotl）→ 太陽高度に関係なく東斜面が金、西斜面が青緑。(b) `grain` を削除。(c) `shadeColor` の基調色比率を 0.32→0.6、`litColor` を 0.62→0.8 | 4.webp の「模様」が「山脈」になる。参照画との距離が最も縮む | 0.5 日 |
| 2 | **落ち影（地平線角マップ）**：チャンク生成時に 8 方位の地平線角を頂点ごとに CPU で焼く（DEM から、1 頂点 8 byte）。フラグメントで太陽方位の 2 方向を補間し `shadow = smoothstep(horizon−ε, horizon+ε, sunElev)` | 低い太陽での立体感。参照画の「金と青の二値対比」はこれ無しには出ない | 1.5 日（Worker 化と同時に） |
| 3 | **面と乱数の見直し**：`ridge` 振幅を 1/3、波長を 2 倍（周波数 260→130）。近傍（サブ衛星点 ±800 km）は level 9、外側は 8 の 2 段 LOD | 格子模様の解消。三角形は +50 % 程度で済む | 0.5 日 |
| 4 | **霞と露出**：大気 `heightScale 1.5→1.15`、`exposure 13→8`、`white 0.9→1.0`、`discHaze 0.15→0.08`；地上 `haze*0.3→0.15`；ブルーム閾値 0.86→0.95、grain 0.008→0.004 | 黒が締まり「ピンボケ」感が消える。地平線の白飛びも同時に改善 | 0.5 日（数値の追い込み含む） |
| 5 | **雲**：高層雲の影 0.55→0.15、雲の地上影 0.74→0.6、`F_DETAIL` に 2 倍スケールの塊層（≈60 km）を 1 つ足す | 3.webp の墨筋が消え、雲に大小のリズムが出る | 0.5 日 |
| 6 | **性能の 3 点セット**：地形 `FrontSide`、大気の步数分岐（地面 6／リム 14）、30 fps 既定＋無操作時 20 fps | 中位 Android での安定と発熱低減。実機で `EXT_disjoint_timer_query` を使って前後計測 | 0.5 日 |
| 7 | **撮影＋現像（M4）に着手**：シャッター 1 ボタン、36 枚、現像はセッション終了時のみ、コンタクトシートを canvas で書き出し、IndexedDB 保存＋Web Share。同時に「前回位置から再開」と `webglcontextlost` 対応 | §14 の主仮説を検証可能にする。これが無いと描画の改善効果を測る物差しが無い | 3〜4 日 |

補足：1〜5 は互いに独立で、いずれも `?style=` のような切替を付けて **同じ場面（4.webp の条件 `?t=` 固定）で前後比較** してから確定するのが art-direction §5 の趣旨に沿う。
