# 低軌道旅行 — 設計叩き台 v0.1

> 作成: Opus（一次案）／ レビュー: Fable 5.1（§12）
> ステータス: 叩き台。「要相談」とされた論点はすべて §11 に選択肢と推奨を併記。

---

## 0. 一行コンセプト

**「操縦しない宇宙旅行」。** ISS相当の軌道に乗った宇宙船の窓から、地球の昼・夜・薄明・気象・大気光を、ただ眺める。プレイヤーが選ぶのは「どこから・何を・どの速さで見るか」だけ。

---

## 1. 体験の設計原則（判断に迷ったらここに戻る）

| # | 原則 | 具体的な帰結 |
|---|------|--------------|
| P1 | **操作より観察** | 宇宙船は操縦不可。失敗・スコア・タイマーによる圧は置かない |
| P2 | **物理は嘘をつかない、描画は飾らない** | 軌道・太陽位置・昼夜境界・季節は計算で正しく。見た目は低ポリ＋フラット＋グラデーションで抽象化 |
| P3 | **外は無音、中は生活音** | 外部カメラ＝ほぼ無音（ドローンのみ）、船内カメラ＝換気ファンのハム・無線。視点切替で音響も切り替わる＝没入感の主要因 |
| P4 | **UIは消える** | 3秒無操作でUIフェードアウト。常時表示は何もない状態をデフォルトに |
| P5 | **偶然性を残す** | 気象・オーロラ・雷は「確率的に起きる」。狙っても必ずは見られない |

## 2. 宇宙船と軌道

### 2.1 軌道モデル（推奨: 簡易ケプラー＋J2歳差）

| 項目 | 値（ISS実値の概数） | 備考 |
|------|------|------|
| 高度 | 約 420 km | 実ISSは約 400–420 km で変動 |
| 軌道傾斜角 | 51.64° | 北緯・南緯約51.6°まで。ロンドン付近まで北上 |
| 周期 | 約 92–93 分 | 1日約15.5周 → 日の出・日の入りが1日約16回ずつ |
| 昇交点歳差 | 約 −5°/日 | J2摂動。これで「毎日違う時刻に同じ場所を通る」 |
| 離心率 | ≈0（円軌道近似） | 視覚上の差はほぼ出ない |

- **選択肢A（推奨・MVP）**: 上記パラメータの円軌道を自前計算。外部通信ゼロ、決定論的、軽い。
- **選択肢B（v2）**: `satellite.js`（SGP4）＋ビルド時に取得したTLEスナップショットを同梱。「今この瞬間の実ISS位置」モードが可能になる。実行時のTLE取得はCORS・可用性が不確実なため、ビルド時取得（GitHub Actions）が安全。
- 太陽方向: 日付からの簡易天文計算（赤緯・均時差）で十分。月も同様に簡易計算（月明かりの海面反射が美しいので月は入れたい）。

### 2.2 宇宙船

- **ISSの形を「思わせる」架空ステーション**（トラス＋太陽電池パドル＋モジュール群＋キューポラ）。NASAロゴ等は使わない（NASAの徽章類は使用ガイドラインで制限あり）。
- 姿勢: ISSの通常姿勢に近い **LVLH固定**（常に進行方向前・地球下向き）。これで「窓の下は常に地球」が保証され、カメラ設計が安定する。

## 3. カメラ（視点）

| ID | 名称 | 種別 | 見えるもの | 操作 |
|----|------|------|-----------|------|
| C1 | キューポラ | 船内 | 真下の地球を7枚窓越し。窓枠が画面を切る＝没入の核 | パン/チルト（窓枠内で制限）、ピンチでズーム |
| C2 | 前方窓 | 船内 | 進行方向の水平線（リム）。日の出が正面から来る | 小パン |
| C3 | 天底カメラ | 船外 | 真下の地表を真上から。地図的 | ズームのみ |
| C4 | トラス後方 | 船外 | 太陽電池パドル越しに後方の地平線。夕焼けがパドルに反射 | パン |
| C5 | リム望遠 | 船外 | 地平線の大気層（薄い青の帯・大気光・夜光雲）を望遠で | ズーム・パン |
| C6 | 追従（外部三人称） | 船外・非現実 | 宇宙船全体＋背後の地球。唯一の「絵葉書」視点 | 軌道カメラ（ドラッグで周回） |
| C7 | 天頂 | 船外 | 星空・天の川・月。夜側では漆黒の闇 | パン |

- MVPは **C1, C3, C5, C6** の4つで十分（船内1・地表1・大気1・外観1で役割が重ならない）。
- 切替はスワイプ左右 or 画面下部の小さなドット。

## 4. 見られる現象（＝コンテンツの本体）

現象は **「条件」×「確率」** で発生させる。実データ連携はしない（MVP）。

| 現象 | 発生条件（簡易） | 主なカメラ | 実装難度 |
|------|-----------------|-----------|---------|
| 軌道上の日の出/日の入り | 太陽‐地球‐船の幾何（自動、1日約16回） | C2, C5 | 低 |
| 明暗境界（ターミネーター） | 常時 | C3, C6 | 低 |
| 大気のリム（青い薄層） | 常時。昼側で明るい | C5 | 中（シェーダ） |
| 大気光（エアグロー、緑の薄帯） | 夜側リム | C5 | 低 |
| 都市光 | 夜側、陸地×人口密度 | C1, C3 | 中（データ） |
| 雷（積乱雲内の閃光） | 夜側・熱帯・現地夕方〜夜で高確率 | C1, C3 | 低 |
| オーロラ | 磁気緯度が高い＋夜側。強度は日替わり乱数（Kp相当） | C4, C5 | 中 |
| 夜光雲（NLC） | 夏至前後・高緯度・薄明帯のリム | C5 | 中 |
| 台風/ハリケーン | 季節×海域で確率生成、渦を数日かけて移動 | C3, C6 | 中 |
| 太陽光の海面反射（サングリント） | 太陽‐海面‐船の鏡面幾何 | C1, C3 | 低（シェーダ） |
| 月光の海面反射 | 同上、月 | C1 | 低 |
| 月の出・月の入り（リム越し） | 幾何 | C2, C5 | 低 |
| 流星（下方に見える） | 流星群の日付で確率増 | C3, C5 | 低 |

> 注: スプライト（高高度放電）は実在するが観測頻度が低く、演出上は「レア」扱いが妥当。発生率の実数値は設計者側で持っていない（不確実）。

## 5. ビジュアル方針（Stylized 3D）

参照: art of rally / Slow Roads の「形を減らし、光と色で語る」方向。

| レイヤ | 手法 | 意図 |
|--------|------|------|
| 地球の陸海 | 低解像度の陸海マスク＋標高段階を**3〜5色の量子化**。テクスチャ写真は使わない | 飾らない。地図でも写真でもない |
| 雲 | ノイズから生成した**平坦な雲シート**（2層）、影は落とすが陰影は2階調 | 「イラストの雲」 |
| 大気 | 物理散乱を正確に解かず、**太陽角→色のグラデーションLUT**でリムと薄明を塗る | 夕焼けの色を「設計」できる。色の管理が最重要 |
| 夜 | 真の黒に近い背景＋都市光の点群（加算合成、わずかなブルーム） | 漆黒の闇を残す |
| 宇宙船 | フラットシェーディング、面ごとに1色、太陽側だけ明るい | 構造が読める最小限 |
| ポスト処理 | 弱いビネット＋フィルムグレイン（任意）。ブルームは最小限 | 「記憶感」。過剰にしない |

- **色が主役**。パレットは「時間帯（太陽高度）」ごとに4〜6キーを持つ1本のLUTで一元管理し、調整を1ファイルに閉じる。

## 6. サウンド

| 層 | 船内カメラ | 船外カメラ |
|----|-----------|-----------|
| 環境音 | 換気ファンのハム（低域、常時） | なし（無音が演出） |
| BGM | 生成型の低いドローン（Web Audioでシンセ生成、ループ感を出さない） | 同じドローンをローパスで遠くに |
| 無線 | 散発的な交信（ノイズ・スケルチ・短い発話風の変調音） | 聞こえない |
| イベント | 日の出の瞬間に1音だけ和音が開く、など極小 | 同左 |

- **無線の発話は「言葉として聞き取れない」処理を推奨**。実NASA音源（多くは米国政府著作物）を使う案もあるが、個別素材の権利状態・エンドースメント誤認のリスクを確認しきれないため、MVPは合成音で行う。
- ブラウザの自動再生制限により、音は**最初のタップ後**に開始（タイトル画面の「出発」タップを兼ねる）。

## 7. 操作（レバー）

### 7.1 MVPで持たせるもの

| レバー | 操作 | 範囲 |
|--------|------|------|
| カメラ選択 | 左右スワイプ | C1〜C7 |
| 視線 | ドラッグ（パン/チルト）、ピンチ（ズーム） | カメラごとに制限 |
| 時間速度 | 右端の縦スライダー（または長押し） | ×1（実時間）/ ×10 / ×60 / ×300 |

### 7.2 「レバーを増やすべきか」への回答

**結論: 操作系のレバー（姿勢・軌道・スラスタ）は増やさない。代わりに「観る行為」に意味を与えるレバーを1〜2個だけ足す。**

根拠:
- 操縦を入れると「上手く操作する」評価軸が生まれ、P1（観察）と衝突する。Slow Roads も運転はさせるが失敗させない設計で、同じ轍を踏まない配慮が要る。
- 一方でカメラと時間だけだと、3〜5分で「見終わった」感覚に陥るリスクが高い（検証していない仮説。プロトタイプで計測すべき）。

足す候補の評価:

| 候補 | 観察の意味を深めるか | P1との衝突 | 推奨 |
|------|------|------|------|
| **シャッター（撮影）** | ◎ 見る→選ぶ行為になる | なし | **採用** |
| **露出（明るさ）** | ○ 夜側の都市光・大気光を「探す」行為になる | なし | **採用（C1/C5のみ）** |
| 「次の日の出まで」スキップ | ○ 待ち時間の短縮 | 弱い（待つことも体験） | v2で検討 |
| 軌道選択（ISS/極軌道/太陽同期） | ○ オーロラ主体の旅など | なし | v2（ステージ選択として） |
| 姿勢制御・スラスタ | × | 強い | 不採用 |
| 船内作業ミニゲーム | × | 強い | 不採用 |

## 8. ゴール設計

「ゴールがわからない」は正しい違和感で、このジャンル（アンビエント/観察系）は**明示的な勝利条件を持たないのが普通**。ただし「帰ってくる理由」は要る。

| 案 | 内容 | 帰ってくる理由 | 静けさとの相性 |
|----|------|--------------|--------------|
| A. ゴールなし | 眺めるだけ | 気分 | ◎（だが離脱が早い） |
| **B. 観測ログ（図鑑）** | §4の現象を初めて見ると日時・緯度経度・カメラと共に1行記録される。未観測は「？」 | 残りの「？」を埋めたい | ○ |
| **C. フィルム1本（36枚）** | 1回の滞在で撮れるのは36枚。撮った写真はコンタクトシート（ベタ焼き）として保存・書き出し | 枚数制限が「選ぶ」緊張と価値を生む | ◎ |
| D. 滞在ミッション | 「180日滞在」を早送りで完走 | 終わりがある | △（時間圧になる） |
| E. 通過通知 | 指定した地点（故郷など）の上空通過を知らせる | 個人的な意味 | ○（v2） |

**推奨: B＋C を軸に、E を後から追加。**
- B が「何を探すか」の地図になり、C が「何を残すか」の判断を生む。
- C の書き出し（コンタクトシート画像）は、そのまま共有・印刷物の素材になる。
- スコアやランキングは付けない。

## 9. 技術構成（GitHub Pages 前提）

| 項目 | 選定 | 理由 |
|------|------|------|
| 描画 | Three.js（WebGL2） | 実績・資料が最多。WebGPUはiOS Safariの対応状況に不確実性があるためMVPでは避ける |
| ビルド | Vite | 静的出力をそのまま Pages へ |
| 言語 | TypeScript | 軌道・天文計算の単位ミスを型で減らす |
| デプロイ | GitHub Actions → Pages | `main` push で自動公開 |
| データ | 陸海マスク・都市光を小さなPNG（各 ≤512KB 目安）で同梱 | 外部API依存ゼロ |
| 音 | Web Audio API（合成） | 音源ファイルを最小化 |

### 9.1 モバイル（横画面）対応

- `screen.orientation.lock('landscape')` は **Android Chrome＋全画面時のみ有効**。iOS Safari では非対応のため、縦持ち時は「横にしてください」の静かなオーバーレイで対応。
- iOS ではホーム画面追加（PWA）で全画面化できるため、manifest を用意。
- 性能: `devicePixelRatio` を最大1.5に制限、FPS監視で解像度を動的に下げる。目標は中位Androidで安定30fps以上、iPhone近年機種で60fps（いずれも未計測の目標値）。
- セーフエリア（ノッチ）を `env(safe-area-inset-*)` で回避。

## 11. 要相談論点のまとめ（一次案の推奨）

| 論点 | 推奨 | 代替 |
|------|------|------|
| 宇宙船の操作 | 不可 | 軌道選択のみ許可（v2、ステージ選択として） |
| ユーザー操作 | カメラ・視線・時間＋**撮影・露出** | カメラ・視線・時間のみ（純粋アンビエント） |
| ゴール | 観測ログ＋36枚フィルム | ゴールなし |
| BGM | 生成型ドローン（控えめ）＋船内は生活音 | BGMなし、環境音のみ |
| 無線SE | 合成音、発話は聞き取れない処理 | 実音源（権利確認後） |
| 実ISS位置 | MVPは簡易軌道、v2でTLE同梱のSGP4 | 実行時TLE取得（CORS不確実） |
