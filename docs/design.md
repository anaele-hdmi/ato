# 低軌道旅行 — 設計叩き台 v0.2

> 作成: Opus（一次案）／ レビュー: Fable 5.1（§12）
> ステータス: 叩き台。§1〜§11 は v0.1 の一次案。**レビュー後の決定は §13（差分）が優先**。

---

## 0. 一行コンセプト

**「操縦しない宇宙旅行」。** ISS相当の軌道に乗った宇宙船の窓から、地球の昼・夜・薄明・気象・大気光を、ただ眺める。プレイヤーが選ぶのは「どこから・何を・どの速さで見るか」だけ。

---

## 1. 体験の設計原則（判断に迷ったらここに戻る）

| # | 原則 | 具体的な帰結 |
|---|------|--------------|
| P1 | **操作より観察** | 宇宙船は操縦不可。失敗・スコア・タイマーによる圧は置かない |
| P2 | **物理は嘘をつかない、描画は飾らない** | 軌道・太陽位置・昼夜境界・季節は計算で正しく。見た目は低ポリ＋フラット＋グラデーションで抽象化 |
| P3 | **外は無音、中は生活音** | 外部カメラ＝ほぼ無音（ドローンのみ）、船内カメラ＝換気ファンのハム・無線。視点切替で音響も切り替わる＝没入感の主要因 |
| P4 | **UIは消える** | 3秒無操作でUIフェードアウト。常時表示は何もない状態をデフォルトに |
| P5 | **偶然性を残す** | 気象・オーロラ・雷は「確率的に起きる」。狙っても必ずは見られない |

## 2. 宇宙船と軌道

### 2.1 軌道モデル（推奨: 簡易ケプラー＋J2歳差）

| 項目 | 値（ISS実値の概数） | 備考 |
|------|------|------|
| 高度 | 約 420 km | 実ISSは約 400–420 km で変動 |
| 軌道傾斜角 | 51.64° | 北緯・南緯約51.6°まで。ロンドン付近まで北上 |
| 周期 | 約 92–93 分 | 1日約15.5周 → 日の出・日の入りが1日約16回ずつ |
| 昇交点歳差 | 約 −5°/日 | J2摂動。主な見た目の効果はベータ角の周期変化（白夜期間）。「毎日違う時刻に同じ場所を通る」の主因は非整数周回（§13で訂正） |
| 離心率 | ≈0（円軌道近似） | 視覚上の差はほぼ出ない |

- **選択肢A（推奨・MVP）**: 上記パラメータの円軌道を自前計算。外部通信ゼロ、決定論的、軽い。
- **選択肢B（v2）**: `satellite.js`（SGP4）＋ビルド時に取得したTLEスナップショットを同梱。「今この瞬間の実ISS位置」モードが可能になる。実行時のTLE取得はCORS・可用性が不確実なため、ビルド時取得（GitHub Actions）が安全。
- 太陽方向: 日付からの簡易天文計算（赤緯・均時差）で十分。月も同様に簡易計算（月明かりの海面反射が美しいので月は入れたい）。

### 2.2 宇宙船

- **ISSの形を「思わせる」架空ステーション**（トラス＋太陽電池パドル＋モジュール群＋キューポラ）。NASAロゴ等は使わない（NASAの徽章類は使用ガイドラインで制限あり）。
- 姿勢: ISSの通常姿勢に近い **LVLH固定**（常に進行方向前・地球下向き）。これで「窓の下は常に地球」が保証され、カメラ設計が安定する。

## 4. 見られる現象（＝コンテンツの本体）

現象は **「条件」×「確率」** で発生させる。実データ連携はしない（MVP）。

| 現象 | 発生条件（簡易） | 主なカメラ | 実装難度 |
|------|-----------------|-----------|---------|
| 軌道上の日の出/日の入り | 太陽‐地球‐船の幾何（自動、1日約16回） | C2, C5 | 低 |
| 明暗境界（ターミネーター） | 常時 | C3, C6 | 低 |
| 大気のリム（青い薄層） | 常時。昼側で明るい | C5 | 中（シェーダ） |
| 大気光（エアグロー、緑の薄帯） | 夜側リム | C5 | 低 |
| 都市光 | 夜側、陸地×人口密度 | C1, C3 | 中（データ） |
| 雷（積乱雲内の閃光） | 夜側・熱帯・現地夕方〜夜で高確率 | C1, C3 | 低 |
| オーロラ | 磁気緯度が高い＋夜側。強度は日替わり乱数（Kp相当） | C4, C5 | 中 |
| 夜光雲（NLC） | 夏至前後・高緯度・薄明帯のリム | C5 | 中 |
| 台風/ハリケーン | 季節×海域で確率生成、渦を数日かけて移動 | C3, C6 | 中 |
| 太陽光の海面反射（サングリント） | 太陽‐海面‐船の鏡面幾何 | C1, C3 | 低（シェーダ） |
| 月光の海面反射 | 同上、月 | C1 | 低 |
| 月の出・月の入り（リム越し） | 幾何 | C2, C5 | 低 |
| 流星（下方に見える） | 流星群の日付で確率増 | C3, C5 | 低 |

> 注: スプライト（高高度放電）は実在するが観測頻度が低く、演出上は「レア」扱いが妥当。発生率の実数値は設計者側で持っていない（不確実）。

## 5. ビジュアル方針（Stylized 3D）

参照: art of rally / Slow Roads の「形を減らし、光と色で語る」方向。

| レイヤ | 手法 | 意図 |
|--------|------|------|
| 地球の陸海 | 低解像度の陸海マスク＋標高段階を**3〜5色の量子化**。テクスチャ写真は使わない | 飾らない。地図でも写真でもない |
| 雲 | ノイズから生成した**平坦な雲シート**（2層）、影は落とすが陰影は2階調 | 「イラストの雲」 |
| 大気 | 物理散乱を正確に解かず、**太陽角→色のグラデーションLUT**でリムと薄明を塗る | 夕焼けの色を「設計」できる。色の管理が最重要 |
| 夜 | 真の黒に近い背景＋都市光の点群（加算合成、わずかなブルーム） | 漆黒の闇を残す |
| 宇宙船 | フラットシェーディング、面ごとに1色、太陽側だけ明るい | 構造が読める最小限 |
| ポスト処理 | 弱いビネット＋フィルムグレイン（任意）。ブルームは最小限 | 「記憶感」。過剰にしない |

- **色が主役**。パレットは「時間帯（太陽高度）」ごとに4〜6キーを持つ1本のLUTで一元管理し、調整を1ファイルに閉じる。

## 6. サウンド

| 層 | 船内カメラ | 船外カメラ |
|----|-----------|-----------|
| 環境音 | 換気ファンのハム（低域、常時） | なし（無音が演出） |
| BGM | 生成型の低いドローン（Web Audioでシンセ生成、ループ感を出さない） | 同じドローンをローパスで遠くに |
| 無線 | 散発的な交信（ノイズ・スケルチ・短い発話風の変調音） | 聞こえない |
| イベント | 日の出の瞬間に1音だけ和音が開く、など極小 | 同左 |

- **無線の発話は「言葉として聞き取れない」処理を推奨**。実NASA音源（多くは米国政府著作物）を使う案もあるが、個別素材の権利状態・エンドースメント誤認のリスクを確認しきれないため、MVPは合成音で行う。
- ブラウザの自動再生制限により、音は**最初のタップ後**に開始（タイトル画面の「出発」タップを兼ねる）。

## 7. 操作（レバー）

### 7.1 MVPで持たせるもの

| レバー | 操作 | 範囲 |
|--------|------|------|
| カメラ選択 | 左右スワイプ | MVPは C1 → C5 → C3 → C6（§13） |
| 視線 | ドラッグ（パン/チルト）、ピンチ（ズーム） | カメラごとに制限 |
| 時間速度 | 右端のトグル＋スキップ | ×1 / ×10、「次の日の出へ」「次の夜へ」（§13で変更） |

### 7.2 「レバーを増やすべきか」への回答

**結論: 操作系のレバー（姿勢・軌道・スラスタ）は増やさない。代わりに「観る行為」に意味を与えるレバーを1〜2個だけ足す。**

根拠:
- 操縦を入れると「上手く操作する」評価軸が生まれ、P1（観察）と衝突する。Slow Roads も運転はさせるが失敗させない設計で、同じ轍を踏まない配慮が要る。
- 一方でカメラと時間だけだと、3〜5分で「見終わった」感覚に陥るリスクが高い（検証していない仮説。プロトタイプで計測すべき）。

足す候補の評価:

| 候補 | 観察の意味を深めるか | P1との衝突 | 推奨 |
|------|------|------|------|
| **シャッター（撮影）** | ◎ 見る→選ぶ行為になる | なし | **採用** |
| **露出（明るさ）** | ○ 夜側の都市光・大気光を「探す」行為になる | なし | **採用（C1/C5のみ）** |
| 「次の日の出まで」スキップ | ○ 待ち時間の短縮 | 弱い（待つことも体験） | v2で検討 |
| 軌道選択（ISS/極軌道/太陽同期） | ○ オーロラ主体の旅など | なし | v2（ステージ選択として） |
| 姿勢制御・スラスタ | × | 強い | 不採用 |
| 船内作業ミニゲーム | × | 強い | 不採用 |

## 8. ゴール設計

「ゴールがわからない」は正しい違和感で、このジャンル（アンビエント/観察系）は**明示的な勝利条件を持たないのが普通**。ただし「帰ってくる理由」は要る。

| 案 | 内容 | 帰ってくる理由 | 静けさとの相性 |
|----|------|--------------|--------------|
| A. ゴールなし | 眺めるだけ | 気分 | ◎（だが離脱が早い） |
| **B. 観測ログ（図鑑）** | §4の現象を初めて見ると日時・緯度経度・カメラと共に1行記録される。未観測は「？」 | 残りの「？」を埋めたい | ○ |
| **C. フィルム1本（36枚）** | 1回の滞在で撮れるのは36枚。撮った写真はコンタクトシート（ベタ焼き）として保存・書き出し | 枚数制限が「選ぶ」緊張と価値を生む | ◎ |
| D. 滞在ミッション | 「180日滞在」を早送りで完走 | 終わりがある | △（時間圧になる） |
| E. 通過通知 | 指定した地点（故郷など）の上空通過を知らせる | 個人的な意味 | ○（v2） |

**推奨: B＋C を軸に、E を後から追加。**
- B が「何を探すか」の地図になり、C が「何を残すか」の判断を生む。
- C の書き出し（コンタクトシート画像）は、そのまま共有・印刷物の素材になる。
- スコアやランキングは付けない。

## 9. 技術構成（GitHub Pages 前提）

| 項目 | 選定 | 理由 |
|------|------|------|
| 描画 | Three.js（WebGL2） | 実績・資料が最多。旧端末のカバレッジとThree.jsでの安定性を優先（WebGPUの対応状況は未確認） |
| ビルド | Vite | 静的出力をそのまま Pages へ |
| 言語 | TypeScript | 軌道・天文計算の単位ミスを型で減らす |
| デプロイ | GitHub Actions → Pages | `main` push で自動公開 |
| データ | 陸海マスク・都市光を小さなPNG（各 ≤512KB 目安）で同梱 | 外部API依存ゼロ |
| 音 | Web Audio API（合成） | 音源ファイルを最小化 |

### 9.1 モバイル（横画面）対応

- `screen.orientation.lock('landscape')` は **Android Chrome＋全画面時のみ有効**。iOS Safari では非対応のため、縦持ち時は「横にしてください」の静かなオーバーレイで対応。
- iOS ではホーム画面追加（PWA）で全画面化できるため、manifest を用意。
- 性能: `devicePixelRatio` を最大1.5に制限、FPS監視で解像度を動的に下げる。目標は中位Androidで安定30fps以上、iPhone近年機種で60fps（いずれも未計測の目標値）。
- セーフエリア（ノッチ）を `env(safe-area-inset-*)` で回避。

## 12. Fable 5.1 レビュー（v0.1に対する辛口レビュー、要点を転記）

### 総評

- 骨格（操縦しない／物理は正しく描画は抽象化／視点で音が変わる）は妥当で、原則の一貫性は高い。
- 最大の穴は**セッション設計の欠落**。1周92分の実時間とスマホの数分セッションが噛み合わず、×60/×300 は天底視点で描画が破綻する。「最初の3分で何が起きるか」が未定義。
- Wake Lock・iOSの音ミュート・ストレージ消失・ピンチ抑止など、「静かに長く眺める」を壊すモバイル固有の論点が抜けている。WebGPU非対応の記述は古い可能性が高い。

### 重大度付き指摘表

| 重大度 | 節 | 指摘 | 修正提案 |
|---|---|---|---|
| **重大** | §7.1 / §4 | 天底の地表角速度は ×1 で約1°/s（7.66 km/s ÷ 420 km）。×60 で約62°/s、×300 で約312°/s＝1周18秒。C1/C3 は完全なスミア。日の出（実時間1〜2分）は ×60 で約2秒 | ×60/×300 を「観る速度」から外し、**「次の日の出／夜側／陸地までスキップ」（フェード付き）**に置換。または高速時は専用の**タイムラプス表現**へ。天底カメラは上限 ×10 |
| **重大** | §4 雷・雲 | ×300 では1フレーム＝実時間5秒。雷が毎フレーム多数発火し常時フリッカー。ノイズ雲の時刻をそのまま倍速すると形が毎フレーム変形 | 現象は**確率レート×dt のポアソン過程**で生成し、高速時は発光の時間積分（淡い持続グロー）へ。雲はUVスクロール＋低速モーフで変形速度に上限 |
| **重大** | §8 / §7.2 | セッションの定義がない。×1 では平均46分に1回しか日の出がない。「3分で何も起きない」リスク | **開始位置ルール**（初回は C1 夜側・日の出2分前から開始。以後は前回位置か「次の見どころ90秒前」）。目標セッション長（例5分）と、その中で最低1現象が起きる保証を書く |
| **重大** | §9.1 | **Screen Wake Lock** 未記載。無操作で眺めると30秒〜1分で消灯し、P1/P4 が崩れる | 最初のタップ後に `navigator.wakeLock.request('screen')`、`visibilitychange` で再取得。非対応時は一度だけ静かに告知 |
| **重大** | §3 / §7.1 | 不整合：MVP は C1/C3/C5/C6 の4視点だが §7.1 は「C1〜C7」 | MVP の視点数と操作範囲を統一、スワイプ順序も明記 |
| 中 | §2.1 | 「毎日違う時刻に同じ場所」の主因は J2 ではなく非整数周回（15.5周/日）。J2 の視覚的主効果は**ベータ角の約60日周期**で、ベータ角 約70°超では**日陰が無くなる（軌道上の白夜）** | 記述修正。白夜期間をレア現象として §4 に追加。夜側が見えない期間の扱いも決める |
| 中 | §2.1 / §4 | 実日付固定だと夜光雲は夏のみ、流星群は特定日のみ。冬開始のユーザーは数か月見られない | 「日付」を第4のレバー（v2）に、または開始日をユーザーごとに乱数化。P2 の「季節は正しく」は「日付に対して整合」の意味に限定 |
| 中 | §8 B案 | 「未観測は？」はコンプリート圧を生み P1/P5 と衝突 | ログは**日誌形式**（見たものだけが時系列に積まれる）、未観測数・総数を表示しない |
| 中 | §8 C案 | 「1回の滞在」「フィルム終了後」が未定義。撮影直後に確認できると選ぶ緊張が薄れる | 滞在＝1本（36枚）。**現像は滞在終了後のみ**。現像時にわずかな偶然（周辺減光・粒状・露出ズレ）を乗せる |
| 中 | §9 | 「WebGPU は iOS Safari で不確実」は古い可能性（Safari 26 で出荷と記憶、確度中） | 理由を「旧端末カバレッジと Three.js の安定性」に書き換え。caniuse で日付付き確認 |
| 中 | §6 | iOS サイレントスイッチで Web Audio 無音（確度中）、割込みで AudioContext が suspended、復帰時 resume が必要 | `statechange` / `visibilitychange` で resume。音が出ないときの視覚的手掛かりを用意 |
| 中 | §6 | 船外でドローンBGMを流すのは P3「外は無音」と自己矛盾 | 船外はドローン**なし**を既定。BGMは設定でオン/オフ |
| 中 | §9.1 | iOS Safari はピンチ/ダブルタップズームを `user-scalable=no` で完全に抑止できない | canvas に `touch-action: none`、`gesturestart` 等を `preventDefault`。PWA推奨。`100dvh` |
| 中 | §9 / §8 | セーブ未記載。Safari は7日間操作のないサイトの storage を消しうる（PWA除外、確度中） | IndexedDB＋**コンタクトシート書き出し（Web Share API）**をバックアップに。消失リスクの許容を明記 |
| 中 | §5 | 後処理ブルームはモバイルのフィルレートを食う | 事前にぼかしたスプライトで代替。ポスト処理はビネット＋グレインの1パス |
| 中 | §5 大気 | (1) リム（大気100km＝地球半径の1.6%）はモバイルで1〜3pxになりエイリアシング、(2) 薄明の層状の色は太陽高度だけでなく視線‐太陽角の2軸が必要 | リムは**スクリーンスペースの解析的リング**で描画。LUT は **2D（太陽高度×視線角）** |
| 中 | §3 / 全体 | 酔い対策なし。地球が視野約140°を占め、ドラッグパン＋高速スクロールでベクション | `prefers-reduced-motion`、カメラ切替はクロスフェード、パン角速度上限、C6 の慣性を短く |
| 中 | §10 | 雲・雷（M2）が音（M3）・撮影（M4）より前。没入と再訪の主要因の検証が後回し | 順序を M0→M1→M3→M4→M2 に |
| 軽 | §2.2 | ISSを強く思わせる形でも混同リスクはゼロでない（非商用試験公開なら実務上小） | クレジットに「非公式・架空」明記。ISS写真は使わない |
| 軽 | §6 | NASA音源は概ねパブリックドメインだが第三者素材・宇宙飛行士の氏名肖像の制限あり（確度中） | 合成音の判断は妥当 |
| 軽 | §7.1 | UI 3秒フェードは初回の発見性を損なう | 初回のみ10秒、以後3秒 |
| 軽 | §4 | 都市光のデータ源が未定 | Natural Earth populated places（パブリックドメイン）または NASA Black Marble 縮小版 |
| 軽 | §9.1 | 60fps 連続描画は熱・電池と相性が悪い | 既定30fps、無操作時はさらに間引き。設定で60fps |

### レビュアーの上位5提案

1. **セッションモデルを冒頭で定義**（目標5分、開始位置ルール、フィルム終了＝現像＝滞在終了）
2. **時間速度を「観る速度（×1/×10）」と「スキップ」に分離**、高速時はタイムラプス表現
3. **写真は現像まで見えない＋現像時の偶然性**。図鑑は現像写真の裏書きとして副産物化
4. **検証計画**：仮説・指標（セッション長、D1/D7再訪、視点別/速度別滞在比率、撮影枚数）・方法（初期は5名の発話思考法、計測は軽量外部 or 計測なしを明示的に選択）。少人数では A/B は無理で被験者内比較が現実的
5. **モバイル必須リスト**：Wake Lock、AudioContext resume、`touch-action: none`、`100dvh`、30fps既定、reduced-motion、クロスフェード、IndexedDB＋書き出し

### レビュアーのMVPスコープ結論

| 判断 | 対象 | 理由 |
|---|---|---|
| 削る | 露出レバー、台風、夜光雲、流星、×60/×300 | 検証したい仮説（撮影で帰ってくるか）に寄与しない |

## 13. Opusによる反映判断（v0.2 への差分）

| 指摘 | 判断 | 反映内容 |
|---|---|---|
| 時間加速の破綻 | **採用** | 時間速度は ×1 / ×10 の2段のみ。代わりに「次の日の出へ」「次の夜へ」スキップ（1秒の暗転）。×60以上は廃止 |
| 現象のポアソン生成 | **採用** | 全現象を「レート×dt」で生成。演出（閃光・和音）は加速に関係なく実時間で再生 |
| セッションモデル | **採用** | 目標セッション5分。初回は C1・夜側・日の出2分前開始。以後は「前回位置」か「次の見どころ90秒前」を選択 |
| Wake Lock ほかモバイル必須リスト | **採用** | §9.1 の必須要件に格上げ |
| 視点数の不整合 | **修正** | MVP は C1 → C5 → C3 → C6（船内→船外、近→遠）の4視点をスワイプ |
| J2 の説明誤り・白夜軌道 | **修正＋追加** | 非整数周回が主因と訂正。白夜期間をレア現象として追加 |
| 季節問題 | **採用（v2）** | MVP は開始日をユーザーごとに乱数化。v2 で「日付」レバー |
| 図鑑のコンプリート圧 | **採用** | ログは日誌形式。総数・未観測数を出さない |
| 現像まで見えない36枚 | **採用** | 滞在＝フィルム1本。滞在終了時に現像→コンタクトシート。現像時の偶然性あり |
| 露出レバー削除 | **採用** | MVP から外す（撮影に集中）。v2 で再検討 |
| 船外は無音 | **採用** | 船外のBGM既定オフ。P3 を厳密化 |
| 2D LUT・解析的リム | **採用** | §5 の大気実装方針を置換 |
| 開発順序 | **採用** | M0 → M1 → 音 → 撮影＋現像 → 現象群 |
| 検証計画 | **採用** | 下記 §14 |
| WebGPU 記述 | **修正** | 選定理由を「旧端末カバレッジと Three.js の安定性」に変更。対応状況は未確認のまま（私の知識でも確定できない） |
